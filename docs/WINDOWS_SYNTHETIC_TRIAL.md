# Isolated writing-first Windows trial

Use `Start-SyntheticTest.cmd` from a newly extracted trial directory. This selects executable-side `SyntheticTest/Data` and `SyntheticTest/UiIdentity`, and disables startup-registration access. Use only synthetic notes, recovery secrets and attachments. Ordinary EXE/portable/install launchers retain their existing paths and are not the approved launch route for this user-PC validation.

The adopted concept was inspected as pixels. Layout corrections center the recovery-code form, move the existing search to the manager toolbar, wrap the sidebar backup-settings heading, and reduce title/body editor borders. All original named controls and command handlers remain. The native window chrome and physical input were not assessed by rendered WPF Window visuals; the result is not claimed pixel-identical to the concept. Additional color/transparency/background-image features remain deferred.

Actual Windows regression exposed a readonly rich-image host whose editor retired after save-status changes while its composite owner remained. The composite now observes status notifications after its children, retires only when the text editor is disposed, and requests a fresh owner through existing generation guards. Ordinary renewable image-action refresh preserves the original editor and Undo. The complete host group and writing UI group passed after this correction, with the original source, ciphertext and revocation assertions retained.

The old installed-package check launches `--portable` and is unsuitable for this bounded PC scope. The new `--synthetic-installed-package <package>` check copies the exact manifest-verified trial to a fresh temporary target, launches the self-contained EXE twice with `--synthetic-test`, checks its packaged runtime, stable isolated UI identity, absent vault and normal exit. It creates no shortcut or startup entry. Malformed synthetic runner selections refuse before constructing a WPF application.

The package includes project-pinned native OCR and its licenses, kor/eng model archive, the self-contained .NET runtime, and a short synthetic-only guide. Package provenance comes from a committed local source revision. Successful packaging/execution and final file hashes must be recorded with each delivered artifact, rather than inferred from this source document.

Known verification limits remain: standard-user symbolic-link fixture creation fails with Windows error1314; these failures are retained without skips, weakened assertions or OS permission changes. Native HKCU startup-registration fixture execution is outside the approved folder-only scope. Physical Korean IME, mixed-monitor DPI movement, OS lock/unlock and manual desktop usability require a supported physical input tool or a user-run check. Automated synthetic WPF checks do not establish those outcomes. Storage/cryptography/schema11/MEMOV002/Android feature contracts are unchanged.
