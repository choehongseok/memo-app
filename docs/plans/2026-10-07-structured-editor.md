# Canonical structured editing and safe Markdown source

## Outcome and data boundary
Continue the approved C01-C12/C15 Windows editor requirements. Keep the shared NoteDraft, encrypted storage, immutable history, synthetic-only tests and all134 IDs. No HTML/XAML execution, automatic links/images/network, clipboard collection, new account, public release or real-data migration. Installer execution is deferred because the existing runner lacks ICE tools.

## Canonical storage
Payload schema4 adds Mode and nullable StyledDocument to notes/revisions. plain/markdown use exact Text source and no rich document; rich has a version1 JSON block document and a validated derived plain-text projection for known documents. Unknown documents retain authenticated Text unchanged, are read-only and cannot claim a faithful TXT export. Rich content is immutable owned SourceJson text, preserving byte-level Unicode/escape/number/whitespace/order source across JSON envelope roundtrips, not serialized WPF XAML/RTF. Parsed JsonElement views are temporary/owned. Existing fields/history/folders/UI remain. Required v4 fields and strict types/bounds/references are checked before state change. v1/2/3 first v4 write retains exact previous ciphertext and failure preserves old files.

Known nodes: paragraph, ordered/unordered list, checklist and table; inline runs carry text, bold/underline/strike, font family/size, foreground/background and optional link. Bounds: JSON1MiB, text65536 UTF16, nodes1024/runs4096/marks bounded, tables32rows/16columns, envelope depth16/total16MiB. All stored text must be well-formed Unicode. Unknown nodes/fields are retained exactly and make the complete rich editor read-only, preventing a lossy WPF projection from overwriting opaque data. Metadata/title operations preserve opaque content. Mode conversion is explicit, warns about formatting/newline loss and creates a new revision with the entire original mode/document in history.

Clone, restore, batch operations, backup/recovery, hidden recovery and schema migration must carry Mode/document without alias/data loss. No direct Text editing of rich drafts; the workspace preflights complete document mutations atomically. Layout changes do not accept unrelated dirty documents.

## Windows projection
A shared WPF document control renders only approved node/run properties and uses real RichTextBox formatting for supported documents. Installed safe font names only; no font URI. Never load user XAML/RTF or URI images. Link text remains inert unless a later explicit, reviewed open action is added. Unknown content is visibly read-only. Management/sticky share one canonical draft and avoid initialization/rebuild/undo feedback loops. Close/lock clears FlowDocument, bindings, undo and cached source references with session/epoch guards.

Markdown stores exact raw source, edited in a normal TextBox. Read-only AST preview never writes back to source. Markdig1.4.0 is a candidate only after independent dependency review: officialNuGet net10.0/no transitive dependencies/BSD-2-Clause/verifiedSHA512, with lockfile and explicit allowlist. DisableHtml, bounded input/AST traversal/projector, inert links/images, no advanced self/media pipelines. Preview failure preserves rawsource. Full CommonMark/GFM fidelity is not claimed for the restricted projector.

## Tests and implementation order
First independent storage/dependency design review, then failing Core fixtures: exact known/opaque document clone/serialization, Unicode and strict v4 fields, document-only revision/history/restore/duplicate/batch, migration/fault/hidden recovery/byte-budget invariance. Implement Core before the WPF projection. WPF red-first tests then real shared editing/formatting/conversion/undo/read-only unknown/locked clear/late callbacks. Existing full Core/source/Python/build/WPF checks remain. Actual IME/physical input/OS locks/ACL and user acceptance stay separate. Source/editor fidelity, not merely successful rendering, is the acceptance boundary.
