# N04 authenticated inline PNG Word export implementation plan

> **Execution record 2026-10-10:** Independent structural PRE and stronger pixel-validation delta PRE reviews found no blocking Critical/Important. The parent authorized Tasks1–3 within the existing continuous development scope; actual prior301 Core missingAPI RED is recorded before production. Authors own separate files; root coordinates builds, independent postreview and publication. No new product dependency, service or user decision is authorized.

**Goal:** Extend the existing selected-note Word command to include every supported canonical v2 image block using its exact authenticated PNG attachment bytes, preserving the encrypted originals.

**Architecture:** The source owner captures an immutable document projection and closed, owned PNG context through existing authenticated attachment leases. A fixed detached data-only worker sequentially validates every unique PNG with the existing bounded `PngPixelDecoder.Decode`, immediately disposes each `OwnedBgraRaster`, then builds bounded DOCX parts. The owner retains authority and buffers until actual worker settlement; Word receives the exact original PNG media, with no new decoder, rendering or transcoding.

**Tech stack:** Existing .NET 10 Core/Windows projects, BCL ZIP/XML/SHA256 and existing PNG structure profile; no product package dependency or Office automation.

**Spec:** `SOURCE_PROMPT.txt` N04 “Word 내보내기”, N05 selected-note export and plaintext disclosure; `PRODUCT_SPEC.md` canonical documents/attachment/root boundaries; `FEATURES.json` N04; `FEATURE_GAP_AUDIT.md` N04; `plans/2026-10-09-office-text-export.md`; `H01_INLINE_IMAGE_PLAN.md`.

## Scope and observed source

N04 explicitly requests Word export. The previous Office plan implemented a disclosed text projection; later `StructuredWordExport` added canonical runs, lists, checklists and tables. The current ledger names attachment image embedding as a remaining gap. H01 excluded Word embedding from its own unit, rather than excluding it from N04. This extension is compatible with that scope and requires no new service, publisher or user approval decision.

`OfficeTextTransfer.Capture(..., Word)` delegates to `StructuredWordExport.Capture`. That method and `MainWindow.OfficeExport.cs` currently refuse every rich document whose `SchemaVersion != 1`, including v2 with zero images. Canonical v1/v2 use the same `nodes` array; `RichDocumentCodec.Images` describes top-level placements by block index, object ID and alt text. Unknown v1 content remains unsupported for complete Word export; image-looking opaque v1 fields never authorize reads. V2 image text projection contains a declared marker; the image-aware Word path must render the image block itself, not silently substitute that marker or render both.

`SaveCoordinator.CreateAttachmentReadLease(note,id,version)` authenticates the current record and immutable object before/after actual vault decryption. The lease is single-use and clears its bytes after the synchronous borrowed callback. `PngPreviewProfile.Inspect` is a bounded CRC/header/chunk check; it explicitly does **not** prove valid decoded pixels. `PreparedTextExport` owns the finished package and `TextTransfer.WritePrepared` uses local-path checks, `CreateNew`, cancellation before/after file creation and durable flush. Existing file failure may leave a partial plaintext file.

## Global constraints

- Preserve exact original source JSON, `Text`, all current/history records, immutable objects, ciphertext, OCR derivations, root/key state, scope and schema1..11 behavior. This is a read-only export; no migration, root preparation, save checkpoint, history change or attachment mutation.
- Supported modes remain plain literal text, Markdown literal source and supported canonical rich v1/v2. Unknown/invalid rich content refuses the whole selected export before destination creation. No rendered Markdown, inline-run images, JPEG/general-format support, external image paths or arbitrary file embedding.
- Existing selection cap100, per-note title256/text65536, canonical source1MiB/node1024/run4096/depth16/token bounds, projected-source aggregate16MiB, canonical-source aggregate16MiB, aggregate emitted XML16MiB and final ZIP16MiB remain. Strict Unicode/XML character validation includes image alt text.
- Unique media cap128, each PNG4MiB, unique plaintext media aggregate8MiB. Before worker launch, accumulate IHDR source pixels across unique authenticated media with checked `long` arithmetic; refuse totals exceeding64,000,000 pixels. The existing profile permits at most4,194,304 source pixels per PNG (not16 million), width/height4096, and a sampled preview at most1,048,576 pixels/4MiB. Count placements separately: at most102400 across100 bounded documents; repeated blocks reuse one media part but retain independent placement and alt text. These caps do not expand vault object/ref limits (16 distinct active refs per note).
- Exact MIME `image/png`, active record-local attachment membership, actual anchored current root and authenticated immutable object descriptors are necessary for an image read. A caller-supplied filename, bytes, hash or public DTO is not authority. Missing/wrong-root/tampered/unreferenced objects refuse the entire export.
- Keep default-No plaintext confirmation, `.docx` local destination outside active vault, new-file-only behavior, no automatic external opening, no macro/font/OLE embedding, no external relationships and no temp plaintext media files. Declare exported image bytes/alt text may remain in external files and viewer caches after app lock.
- Reuse the existing bounded managed decoder solely to validate pixel stream semantics; preserve original PNG bytes including alpha and bounded scalar ancillary chunks. Structure alone does not suffice for export. Decoder success proves acceptance by this closed profile, not safety or exact appearance in every external viewer. Unknown chunks/APNG/interlace/profile variants rejected by the existing profile remain rejected. No new decoder/native codec or pixel re-encoding is introduced.

## Review focus

1. Shared object A→B and old-session/reopen replay: an image identity does not substitute for the original selected-note authority (Task1/3).
2. Lock/selection/edit during capture, ZIP disposal or blocked file creation: no later write starts after revocation; held buffers/slot retire only at actual settlement (Task1/3).
3. Repeated images, zero-image v2 and mixed selection: each canonical block is represented once, with no silent partial export (Task2).
4. ZIP compression cannot hide unbounded XML/media or final central-directory growth; cleanup covers failures and retired growth buffers (Task2).
5. CRC-valid malformed PNG pixel streams must refuse the whole export before destination creation; decoder acceptance, independent package checks and external viewer acceptance are separate evidence (Task2/3).

## Closed source context and authority

Proposed internal APIs (names subject only to coordinated signature changes before implementation):

- New `Transfer/OwnedWordImageContext.cs`: sealed internal `OwnedWordImageContext : IDisposable` with immutable `WordNoteSource` values (title, mode, text, owned canonical source), placement values and private owned PNG arrays. Constructors and mutation inaccessible to public callers. No note, workspace, vault, root key, session, dispatcher or UI callback fields. Metadata may identify objects/root/hash/length; it confers no independent read authority.
- New `Editing/SaveCoordinator.WordExport.cs`: internal `CaptureWordImageContext(IReadOnlyList<NoteDraft> selection, IReadOnlyList<long> expectedVersions, long expectedPreviewEpoch, CancellationToken token)` returns that closed context. Coordinator issuer state admits at most one outstanding context before authentication/decryption/allocation. The selected owner is captured by exact draft instances/order, original workspace, session epoch/nonce, versions and global preview epoch; a live requested note/version alone cannot renew an old grant. The admission token stays owner-side and never enters the worker.
- New or extracted internal `StructuredWordExport.Build(OwnedWordImageContext context, CancellationToken token) -> PreparedTextExport`. Existing public `Capture(selection)` continues to support its current no-authority v1/plain route and refuse image-backed input; public note-only capture must not gain attachment access. The image-aware path is internal and accepts only the closed coordinator-produced context. Prefer reusing one writer through detached no-image capture rather than two rich renderers.

Before creating any PNG array, validate bounded selection and every supported document, precompute unique object descriptors and media totals, and verify each placement against that selected record's current refs/root/object. Recheck pure owner state before and after any external host callback. Capture source fields once; require each supported rich projection equals the note's stored `Text`. Reserve all bounded metadata before decryption where feasible.

Consume authenticated leases sequentially, each exactly once. In the same borrowed callback, compare exact length and SHA256 with the previously captured immutable descriptor, inspect that same span through `PngPreviewProfile`, then copy into its one owned bounded PNG buffer. No second read, public bytes constructor, or structure-only authorization path. If `Consume` returns false after a revoke, discard the copied buffer. Recheck the original whole selection/versions/epoch/object bindings after each read and final capture. Deduplicate only identical authenticated object identity/root/hash/length; never use source names for part names or merge distinct objects solely by equal content hash.

No callbacks/events are raised by context disposal from the worker. Owner-side revocation cancels a token and marks the grant unusable; it must not zero a live worker's buffers. Register context retirement with coordinator conceal/source invalidation/session disposal; the host additionally watches exact selection changes/close. Completed-but-unwritten contexts retire on cancellation/disposal. Running contexts remain admitted until worker completion and cleanup actually settle, even if their cancellation token fires. Removal/unsubscription must not release the slot while worker-owned bytes remain live.

## DOCX representation and budgets

Continue emitting the current title/runs/styles/list restart/check-state/table/inert-URL projection in original selection/block order. For a canonical image block emit one paragraph with `w:r/w:drawing/wp:inline/a:graphic/a:graphicData/pic:pic`, image relationship via `a:blip r:embed`, and matching transform/extent. Use unique checked drawing IDs per placement; `wp:docPr` description carries escaped alt text and generated inert names. No UUID/name/path is interpolated as package syntax.

Generated media names are `word/media/image0001.png` etc. `word/_rels/document.xml.rels` retains numbering and adds unique internal image relationships targeting `media/image0001.png`; `[Content_Types].xml` adds the PNG default `image/png`. Media bytes are exactly the authenticated owned bytes. No `TargetMode=External`, hyperlinks, embedded external file references, thumbnail, macro, custom XML or document properties containing source paths.

Use a fixed portrait A4 section (11906×16838 twips) with1440-twip margins. Derive layout from validated IHDR width/height at96DPI, checked integer EMU conversion (9525 EMU/pixel), proportionally fit within the resulting page content box, never upscale, ignore optional pHYs for placement, preserve original PNG metadata unchanged. Pin rounding and positive extents in tests; the external Word viewer controls actual rendering and pagination.

Before constructing any ZIP/package media, the fixed worker validates all unique PNG arrays in sequence using `PngPixelDecoder.Decode(source, token)`. Check cancellation before and after each decode, dispose the returned raster immediately in a `using` scope, and retain no decoded pixels. Existing decoder row-loop cancellation, exact stream end/filter/zlib/Adler checks and finally cleanup remain unchanged. Only one sampled output raster (at most4MiB), two scanline arrays (each at most16384 bytes) and one compressed IDAT copy (at most4MiB) may coexist in this phase; do not accumulate rasters or decode repeated placements again. Source pixel totals are independently recomputed by the worker before decoding and must match the bounded captured descriptors. Invalid media yields no package result and no destination file. Cancellation/revocation keeps admission until the actual worker settles, including raster/row/compressed-copy teardown.

Account unique media8MiB separately from XML16MiB and package16MiB. Maximum ZIP entries are5 existing parts+128 media=133. Write PNG as uncompressed ZIP entries because PNG already compresses its pixels; regardless of compression mode, enforce uncompressed media bytes and package bytes during writes. Keep the hard zeroing package stream active through `ZipArchive.Dispose` so central-directory overflow refuses before any file exists. Cancellation checks surround parsing/each block/media chunk and finalization/ownership transfer. No uncapped `ToArray` intermediary: final copy is bounded, with finally clearing construction/retired buffers and unused final buffer on failure. Owned source arrays clear on capture failure/cancellation/dispose; package bytes clear after the writer settles. Managed immutable strings/XML allocations are bounded but cannot claim guaranteed GC memory erasure.
